Shell speed: slice logs in seconds

By the end you can: turn a raw log into a ranked answer with one pipeline, and move around a terminal without reaching for the mouse.

U is utilization, S is saturation, E is errors. Lit lamps mark what this lesson examines.

Recall first

Before new material, pull these from memory. Struggling here is useful: it is what makes the earlier lesson stick.

In /proc/PID/fd, each entry represents a…

  • Open file or socket
  • Running child process entry
  • Loaded kernel module image
  • Pending signal queue entry

Every open file, socket, or pipe appears as an entry under /proc/PID/fd.

Everything so far produced text: counters, logs, tables. Under pressure, the person who can slice that text fastest answers first. This lesson is about speed, and about not making things worse while you hurry.

One shape covers most questions

“Who is hammering us?” “Which path is failing?” “When did it start?” They are all the same pipeline: filter, extract a field, group, count, rank, trim.

flowchart LR
  A["Filter: grep or an awk condition"] --> B["Extract: awk or cut a field"]
  B --> C["Group: sort"]
  C --> Dq["Count: uniq -c"]
  Dq --> E["Rank: sort -rn"]
  E --> F["Trim: head"]

$ awk '{print $1}' access.log | sort | uniq -c | sort -rn | head
$ awk '$9 >= 500 {print $4}' access.log | cut -c2-18 | sort | uniq -c
$ journalctl -u api --since "1 hour ago" -o cat | sort | uniq -c | sort -rn | head
$ ss -tan | awk 'NR>1 {print $1}' | sort | uniq -c | sort -rn

Why sort before uniq -c? uniq only collapses adjacent duplicates, so unsorted input gives meaningless counts. The final sort -rn ranks the counts, biggest first. In the second line, field 9 of a standard web-server access log is the status code, and field 4 is the timestamp; cut -c2-18 trims it to the minute.

Keep the terminal under you

  • tail -F file follows a log even across rotation. less +F does the same and lets you scroll back.
  • watch -n1 'ss -s' turns any command into a live display.
  • Ctrl-R searches history. !! repeats the last command, so sudo !! reruns it with sudo. !$ is the last argument. cd - returns to the previous directory.
  • Ctrl-A and Ctrl-E jump to the line’s start and end; Ctrl-W deletes a word; Ctrl-U clears to the start.
  • Run long work inside tmux new -As incident, so a dropped connection does not kill your session or your diagnosis.

Hurry safely

Reads are free; writes are not. Run the read-only version of a command first: ls the glob before rm it, echo a loop before you let it run. Send kill -TERM before kill -9. Never paste a destructive command you have not read, including one a teammate wrote in chat. Speed that causes a second outage is slower than care.

Predict first. What does sort | uniq -c | sort -rn | head do to a list of IP addresses, and what breaks if you drop the first sort?

It counts occurrences of each address and shows the most frequent first. Without the first sort, identical addresses are not adjacent, so uniq -c produces many small counts instead of one total per address.

Drill with a real log

Find the noisy client and the bad minutes

Download sample-access.log (635 requests, standard access-log format). Answer from the shell, then open the answers.

  1. Which client IP sent the most requests, and how many?
  2. Which minutes had the most responses with status 500 or above? List the top three.
  3. What one more command would you run to see what that client was requesting?
Check your answers

1. awk '{print $1}' sample-access.log | sort | uniq -c | sort -rn | head -3 ranks 203.0.113.9 first with 75 requests.

2. awk '$9 >= 500 {print $4}' sample-access.log | cut -c2-18 | sort | uniq -c | sort -rn | head -3 gives [08/Nov/2026:10:17 at 38, [08/Nov/2026:10:15 at 34, and [08/Nov/2026:10:16 at 29.

3. For example grep '^203.0.113.9' sample-access.log | awk '{print $6, $7, $9}' | sort | uniq -c | sort -rn. It shows the same address repeatedly posting to /api/login with errors.

Check yourself

Why must sort come before uniq -c?

  • uniq counts only adjacent duplicates
  • sort deletes lines uniq dislikes
  • uniq cannot read standard input
  • sort converts text to numbers

uniq compares neighboring lines only, so sorting first makes identical lines adjacent.

Which shortcut reruns the previous command using sudo?

  • sudo ^^
  • sudo !!
  • sudo $?
  • sudo !$

!! expands to the previous command line, so sudo !! reruns it with elevated privileges.
