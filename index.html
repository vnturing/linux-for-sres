Linux for Aspiring Platform Engineers and SREs

You can already install packages and fix small problems at your own pace. This course builds what comes next: reading a struggling server in its first minute, and acting on what you read while someone is waiting.

Four resources, three questions each. The whole course is about learning to read this panel on a real server.

How the course works

  • Sequential. Each lesson starts from the one before it and adds one idea.
  • Short. Eight to fifteen minutes. One tangible skill per lesson.
  • Active. Every lesson has a prediction prompt, a hands-on drill, and a quiz. Every lesson after the first opens with a recall question from earlier, because retrieving something is what makes it stay.
  • Sourced. Claims link to their sources: kernel documentation, man pages, and practitioners such as Brendan Gregg, Netflix’s performance team, Google’s SRE book, and Julia Evans.

You need a disposable Linux VM with sudo (Debian or Ubuntu family; examples use apt and systemd). Never run the drills on a production machine.

Module 1: Think before you type

  • 01Start with the question, not the toolYou will write a four-line problem statement and a ranked hypothesis list before you touch the keyboard.8 min
  • 02Four resources, three questionsYou will ask utilization, saturation, and errors of each of CPU, memory, disk, and network, and say which signal is which.10 min
  • 03The first 60 secondsYou will run ten standard commands on a struggling server and place each result in the USE matrix.12 min

Module 2: Read the four resources

  • 04Load average is a queue, not a percentageYou will read a load average, decide whether the CPU, the disk, or a hypervisor is behind it, and prove it with two commands.12 min
  • 05Memory: free is the wrong numberYou will tell healthy cache use from real memory pressure, and find an OOM kill after the fact.12 min
  • 06Disk: full, slow, or bothYou will diagnose “no space left on device” including the deleted-but-open-file case, and read iostat for a slow disk.14 min
  • 07Network: refused, timed out, or slow?You will classify a connectivity failure from one command’s behavior and pick the next check.14 min

Module 3: Processes and services

  • 08Services: systemd is your first responderYou will take a failing or flapping service from “it’s down” to an exit status and a log line in under two minutes.14 min
  • 09Seeing inside a processYou will tell a stuck process from a busy one, spot a file-descriptor leak, and read a strace line.14 min

Module 4: Work under pressure

  • 10Shell speed: slice logs in secondsYou will turn a raw log into a ranked answer with one pipeline, and move around a terminal without reaching for the mouse.15 min
  • 11Mitigate first, diagnose secondYou will choose a reversible mitigation, capture evidence before changing anything, and keep a timeline.14 min
  • 12Capstone: practice under the clockYou will run timed troubleshooting scenarios, log them in a reusable format, and schedule the review that makes the skills stick.15 min
