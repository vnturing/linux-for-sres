# Mission: Linux for Aspiring Platform Engineers and SREs

## Why
Software engineers who are comfortable enough with Linux to install packages and fix small problems at their own pace want to move into platform engineering and SRE roles, where they must read and act on a struggling Linux server while someone is waiting.

## Success looks like
- Run a disciplined first minute on an unfamiliar, struggling server and say which of CPU, memory, disk, and network is implicated, or exonerated.
- Triage a failing service from status, journal, and kernel log to an exit status and a likely cause.
- Choose a reversible mitigation, and capture evidence before it destroys any.
- Slice logs with shell pipelines fast enough to keep up with an incident channel.
- Complete timed troubleshooting scenarios on live broken servers and explain the reasoning.

## Constraints
- Learners build ideas sequentially; each lesson rests on the previous one.
- Hands-on drills use a throwaway Linux VM, never production. Examples assume a Debian or Ubuntu family system with systemd.
- Lessons are short (about 8 to 15 minutes) and end in retrieval practice.

## Out of scope
- Kubernetes, containers orchestration, and cloud-provider specifics.
- Configuration management and infrastructure as code.
- Kernel development and deep eBPF programming.
- Security hardening and compliance.
